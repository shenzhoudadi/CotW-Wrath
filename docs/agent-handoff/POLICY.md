# 开发与交付约定

本文件整理当前有效用户要求。用户最新明确要求：已交付功能默认作为可用基线，每次出包只验证新增/修改内容；去掉冗余检查并立即删除冗余文件。该要求覆盖旧的全历史回归、证书闭包、先发布再清理及须另行确认精简方案的规定。

每个工作包是一项独立功能、完整变体或边界明确的修复，列明内容、依赖、文件、共享机制、冲突风险、完成条件及定向测试。同一变体的必要能力合并；共享机制单独建立行为合同。独立包可隔离并行，共享生产文件统一整合，不为并行重复基础机制。

新增/修改内容只做一次必要定向检验，不因说明、打包、上传重复运行，不检验全部历史内容和依赖。默认构建只编译当前项目、打包并核对包内必要文件/DLL，不自动跑测试套件。历史回归、启动多场景、核心规则、双运行时及整套专项只作可选诊断。实际报错对log修复，用户接受玩家继续发现问题；实际失败和未测范围如实说明，不冒称全历史或游戏验收通过。

冗余验证和旧夹具精简已有用户直接授权，不再为同项重复询问确认。保留当前运行/编译和定向检查必需的输入，不要求恢复全部旧指纹或历史环境。065旧索引缺失与原严格失败保留为真实历史事实，不能声称原件已恢复；旧证据闭包不再阻断当前出包。

必要出包程序自行完成，无需逐次询问或汇报。发布上传和GitHub/原Drive下载回读按具体交付任务执行，保留正式交付原件和云端旧文件。不扩张迁移范围，不把未执行检查声称为PASS。

沿用现有 Harmony 和提供方兼容合同，不启动游戏或 UMM，不把托管检查记为玩家通过。游戏内自有文字保持英文。用户排除、原生及其他模组已覆盖内容不重新加入；已有变体不重复迁移。
# 每次修改后的历史数据维护

每次修改后利用已有索引检查新增产物与历史冗余，直接清理缓存、过期副本、废弃测试尝试和重复依赖，不强制生成另一份大归档。保留当前源码、必要运行/编译依赖、本轮有用测试与正式交付原件。记录真实清理项及释放空间；若执行被系统阻止，明确说明没有删除。

最新用户要求立即精简验证和冗余文件，覆盖此前先完成66再清理的顺序。未收到新发布指令时，不因清理任务自行上传或启动游戏。
