# 开发与交付约定

本文件整理当前有效用户要求。新直接要求优先于历史说明；旧文件里的清理授权已被“保留所有旧文件”覆盖。

每个工作包是一项独立功能、完整变体或边界明确的修复，列明内容、依赖、文件、共享机制、冲突风险、完成条件及定向测试。同一变体的必要能力合并；共享机制单独建立行为合同。独立包可隔离并行，共享生产文件统一整合，不为并行重复基础机制。

每包完成真实正反例及原生调用路径检查，保存源码、DLL、依赖指纹和原日志。失败原件保留，不删除断言、不降阈值、不缩小覆盖。各包统一整合后执行完整构建、历史回归、最终安装包 DLL 检查及独立只读复查，全部满足后统一版本与正式发布，不逐包发版。

可恢复门禁或接受方式变更须先提出独立方案并确认。只有全部相关输入与依赖指纹一致、成功记录完整可核验才考虑复用；受影响步骤重跑。已确认的 065 历史索引接续方案仍永久记录原字节缺口，只允许对具体已声明项用经核验的新重测接续，其他缺失继续阻断。

必要的出包前程序自行走完，无需逐次汇报或确认。正式交付上传 GitHub 与原 Drive 位置并实际下载核对原字节；保留本地与云端全部旧文件。此授权不扩张新迁移范围，也不授权删除文件或跳过门禁。

沿用现有 Harmony 和提供方兼容合同，不启动游戏或 UMM，不把托管检查记为玩家通过。游戏内自有文字保持英文。用户排除、原生及其他模组已覆盖内容不重新加入；已有变体不重复迁移。
