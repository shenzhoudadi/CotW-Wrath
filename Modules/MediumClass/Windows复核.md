# MediumClass 0.3.4 Windows 复核（2026-09-30）

结论：三项用户需求都已落实；Windows 构建与相关检查通过，可交测试者实测。原 Claude 交付保留在 D:/交付文件/通灵。此处安装包是 Windows StageMod 重新生成的版本，另含本轮发现并修正的旧档来源记录问题。

## 复核发现与处理

- 原 0.3.4 进度迁移对多层能力调用 RankToSource.RemoveAll，再只 RemoveRank 一次。若两层的来源进度和等级相同，会删掉两条来源记录却仅减一层，破坏剩余层的记录。
- 原生 Feature.SetSource 会为每个尚缺记录的能力层填入给定来源/等级；RemoveRank 本身不维护 RankToSource。因此同来源同等级的多条记录并非必须视为无效数据。
- 现改为 FindLastIndex + RemoveAt：每个移除计划只删除一条匹配记录；无匹配项时不减层。原 TypeId/GUID 未改动。
- 增加两组回归：仅通灵者来源的重复记录、重复通灵者来源加其他职业来源。检查层数、每层记录数量、保留来源、主来源和再次迁移的幂等性。原源码负对照确实失败，修正后通过。
- 测试指引同步纠正：缚灵者的选择项/无法核实来源提示可以在每次读档记录，并不意味着再次授予或删除能力；只要求没有新的 granted missing/removed 迁移。

## 关于旧涌动重投

0.3.3 没有保存统一骰点，而且原本各属性分别投骰，无法无歧义地还原一份新的统一结果。升级时，仍在生效的旧涌动首次恢复可能重投一次；该效果最多持续五轮。0.3.4 新运行时数据保存 Version/Sides/Results/Announced，模型中的保存恢复不会重投。真实旧档转新档后再读，以及 0.3.4 新档读写，均须按测试指引实测，不能承诺已经在游戏验证。

另有两个保留限制：缚灵者旧档多得/少得的额外专长选择不自动增删；缺少完整每层来源记录的早期多层能力不自动迁移，提示日志并提供重训方案。
